Dynamic imports: downloaded, then re-rendered

This app is a guest component running inside QuickJS in a Web Worker inside a sandboxed iframe (icecream-sandbox). It starts with nothing downloaded. Press Load formatter and the guest asks the host, at that moment, to import the real d3-format package by name — the host asks you to approve the download origin, the module downloads, and the guest re-renders with it. That is a dynamic import: downloaded when needed, then re-rendered.

Press Try the import() version and the same app restarts as a module whose first line is import { format } from 'd3-format'. It renders immediately from the cache: no new prompt, no new download. Once a module is downloaded, it stays cached.

The two paths differ only in when the name is known. A literal import('d3-format') is visible in the code, so the sandbox downloads it up front with the rest of the import graph and evaluates it lazily when import() runs. A computed name (a variable) cannot be known ahead of time, so the guest calls host.importModule(name) instead, which downloads through the same gate and cache at call time. Either way, the app decides which packages exist via the import map — the guest only picks among them.
